# PROJECT_SPEC.md

## 1. Суть проекта

Desktop-приложение-наставник для клиента нутрициолога под Windows.

Нутрициолог передаёт клиенту `.exe` или ссылку на скачивание. Клиент запускает программу на Windows, видит приветствие нутрициолога, заполняет анкету и получает персональную программу питания, привычек и ежедневных действий.

Приложение не просто выдаёт план один раз, а сопровождает клиента внутри программы:
- показывает текущий день;
- даёт задание дня;
- показывает привычку дня;
- даёт рекомендации;
- показывает настрой дня;
- даёт короткие поддерживающие сообщения;
- предлагает отметить выполнение;
- фиксирует выполненные и пропущенные дни;
- считает прогресс;
- помогает мягко вернуться в программу после пропуска.

Клиент возвращается в приложение в любое время: сегодня, завтра или после пропуска. Программа помнит его данные, текущий день, прогресс, выполненные и пропущенные дни.

Программа не заменяет врача, психолога или нутрициолога. Она только помогает клиенту проходить программу, отмечать действия, видеть прогресс и получать мягкие поддерживающие сообщения.

## 2. Стек

- Tauri
- React
- TypeScript
- Tailwind CSS
- Local JSON storage
- GitHub Raw JSON для обновления материалов

## 3. Ограничения MVP

В MVP не делаем:
- личный кабинет;
- сервер;
- оплату;
- сложную AI-генерацию;
- базу данных;
- онлайн-отчёты нутрициологу;
- автообновление `.exe`;
- админку для нутрициолога.

Программа строится по шаблонам на основе анкеты.

Материалы через GitHub Raw JSON обновляет разработчик. Админку, Google Sheet или Supabase можно добавить позже.

## 4. Сценарий передачи клиенту

1. Нутрициолог получает готовый `.exe`.
2. Отправляет клиенту файл или ссылку на скачивание.
3. Клиент скачивает программу.
4. Запускает её на Windows.
5. Видит приветствие нутрициолога.
6. Заполняет анкету.
7. Получает персональную программу.
8. Клиент возвращается в приложение в любое время: сегодня, завтра или после пропуска.
9. Программа помнит его данные, текущий день, прогресс, выполненные и пропущенные дни.
10. Если клиент пропустил день, программа мягко возвращает его в процесс.
11. Если появились новые материалы, программа подтягивает их из интернета и сохраняет локально.

## 5. Анкета клиента

Поля анкеты:
- имя клиента;
- возраст;
- рост;
- вес;
- цель;
- срок программы: 7 / 14 / 21 / 30 дней;
- ограничения по питанию;
- уровень активности;
- текущие привычки;
- основные сложности;
- желаемый результат.

## 6. Длительность программы

Клиент выбирает срок:
- 7 дней;
- 14 дней;
- 21 день;
- 30 дней.

От срока зависят:
- количество дней в календаре;
- количество ежедневных заданий;
- прогресс;
- рекомендации;
- итоговый экран.

## 7. Основные экраны

1. StartPage — стартовый экран с приветствием нутрициолога.
2. AboutNutritionistPage — экран "О нутрициологе".
3. QuestionnairePage — анкета клиента.
4. BuildingProgramPage — экран сборки программы.
5. DashboardPage — главный экран наставника.
6. CalendarPage — календарь программы.
7. DayPage — экран дня.
8. RecommendationsPage — рекомендации.
9. ProgressPage — прогресс.
10. FinishPage — итоговый экран.
11. UpdatesPage — экран обновлений и материалов.
12. SettingsPage — настройки.

## 8. Стартовый экран

Должен показывать:
- имя нутрициолога;
- приветствие;
- короткое описание программы;
- кнопку "Начать программу";
- кнопку "Продолжить", если программа уже создана;
- статус "Онлайн / Офлайн";
- версию материалов.

## 9. Главный экран наставника

Должен показывать:
- текущий день программы;
- цель клиента;
- прогресс;
- серию выполнений;
- задание дня;
- привычку дня;
- настрой дня;
- поддерживающее сообщение;
- кнопку "Открыть сегодняшний день".

## 10. Экран дня

Должен показывать:
- номер дня;
- настрой дня;
- фокус дня;
- привычку дня;
- задание дня;
- чек-лист;
- рекомендацию;
- кнопку "Отметить день выполненным";
- мягкий итог дня после выполнения.

## 11. Календарь

Должен показывать:
- дни программы;
- статус дня: будущий, текущий, выполнен, пропущен;
- визуальный прогресс.

## 12. Экран обновлений

Должен показывать:
- текущую версию материалов;
- дату последнего обновления;
- статус Онлайн / Офлайн;
- кнопку "Проверить обновления";
- блок "Что нового".

## 13. Экран настроек

Должен показывать:
- изменить анкету;
- пересобрать программу;
- сбросить прогресс;
- проверить обновления;
- путь к локальным данным;
- версию приложения;
- версию материалов.

## 14. Модули MVP

### questionnaire
Анкета клиента и типы данных.

### programBuilder
Сборка программы по шаблонам на основе анкеты.

### progress
Выполненные дни, пропущенные дни, процент прогресса.

### clientCoach
Ежедневное сопровождение клиента.

### behaviorAnalysis
Локальный анализ прохождения:
- выполненные дни;
- пропущенные дни;
- серия выполнений;
- серия пропусков;
- возврат после пропуска.

### support
Поддерживающие сообщения:
- настрой дня;
- сообщение внутри дня;
- сообщение после выполнения;
- сообщение после пропуска;
- сообщение для возвращения в программу.

### sync
Проверка и загрузка новых материалов из GitHub Raw JSON.

### storage
Локальное хранение JSON.

### branding
Брендинг нутрициолога:
- имя;
- логотип;
- контакты;
- приветствие;
- описание подхода.
