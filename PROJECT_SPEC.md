# PROJECT_SPEC.md

## 1. Суть проекта

Desktop-приложение-наставник для клиента нутрициолога под Windows.

Нутрициолог передаёт клиенту `.exe` или ссылку на скачивание. Клиент запускает программу на Windows, видит приветствие нутрициолога, заполняет анкету и получает персональную программу питания, привычек и ежедневных действий.

Приложение не просто выдаёт план один раз, а сопровождает клиента внутри программы:

- показывает текущий день;
- даёт задание дня;
- показывает привычку дня;
- даёт рекомендации;
- показывает настрой дня;
- даёт короткие поддерживающие сообщения;
- предлагает отметить выполнение;
- фиксирует выполненные и пропущенные дни;
- считает прогресс;
- помогает мягко вернуться в программу после пропуска;
- показывает меню и рекомендации по питанию;
- помогает адаптировать питание под реальную жизнь клиента.

Клиент возвращается в приложение в любое время: сегодня, завтра или после пропуска. Программа помнит его данные, текущий день, прогресс, выполненные и пропущенные дни.

Программа не заменяет врача, психолога или нутрициолога. Она только помогает клиенту проходить программу, отмечать действия, видеть прогресс и получать мягкие поддерживающие сообщения.

## 3. Ограничения MVP

В MVP не делаем:

- личный кабинет;
- сервер;
- оплату;
- сложную AI-генерацию;
- базу данных;
- онлайн-отчёты нутрициологу;
- автообновление `.exe`;
- админку для нутрициолога;
- медицинские назначения;
- точный лечебный рацион;
- сложный расчёт КБЖУ как в профессиональных сервисах питания.

Программа строится по шаблонам на основе анкеты.

Материалы через GitHub Raw JSON обновляет разработчик. Админку, Google Sheet или Supabase можно добавить позже.

---

## 4. Сценарий передачи клиенту

1. Нутрициолог получает готовый `.exe`.
2. Отправляет клиенту файл или ссылку на скачивание.
3. Клиент скачивает программу.
4. Запускает её на Windows.
5. Видит приветствие нутрициолога.
6. Заполняет анкету.
7. Получает персональную программу.
8. Клиент возвращается в приложение в любое время: сегодня, завтра или после пропуска.
9. Программа помнит его данные, текущий день, прогресс, выполненные и пропущенные дни.
10. Если клиент пропустил день, программа мягко возвращает его в процесс.
11. Если появились новые материалы, программа подтягивает их из интернета и сохраняет локально.

## 5. Анкета клиента

Анкета нужна, чтобы программа могла подобрать питание, привычки, задания, рекомендации и сопровождение под клиента.

Поля анкеты:

- имя клиента;
- возраст;
- рост;
- вес;
- цель;
- срок программы: 7 / 14 / 21 / 30 дней;
- местоположение клиента;
- сезон или текущий период года;
- бюджет на питание;
- доступность продуктов;
- количество приёмов пищи в день;
- обычный рабочий график;
- время подъёма и сна;
- уровень активности;
- ограничения по питанию;
- продукты, которые клиент не ест;
- продукты, которые клиент любит;
- текущие привычки;
- основные сложности;
- частые срывы;
- тяга к сладкому;
- вечерние перекусы;
- желаемый результат.

## 7. Учет доступности продуктов

Приложение должно учитывать, что продукты доступны не всем клиентам одинаково.

При подборе меню нужно учитывать:

- местоположение клиента;
- сезон;
- бюджет;
- доступность продуктов;
- привычные продукты региона;
- ограничения по питанию;
- предпочтения клиента;
- возможность замены продуктов.

Базовое меню должно строиться на широкоиспользуемых и доступных продуктах.

Редкие, дорогие или сезонно нестабильные продукты можно предлагать только как дополнительные варианты, а не как основу программы.

Примеры базовых продуктов:

- крупы;
- яйца;
- курица;
- рыба доступного сегмента;
- овощи по сезону;
- замороженные овощи;
- картофель;
- капуста;
- морковь;
- свёкла;
- яблоки;
- бананы;
- бобовые;
- орехи в умеренном количестве;
- молочные продукты, если у клиента нет ограничений.

Для каждого блюда желательно иметь замены:

- если продукт недоступен;
- если продукт дорогой;
- если клиент его не ест;
- если продукт не подходит по ограничениям.

Логика меню:

- базовый вариант — простые доступные продукты;
- альтернатива — более разнообразный или дорогой вариант;
- замена — простой продукт на случай недоступности.

## 8. Программа питания

Программа должна помогать клиенту понять, что есть в течение дня.

В MVP питание строится по шаблонам, а не через сложную AI-генерацию.

Программа питания должна учитывать:

- цель клиента;
- длительность программы;
- бюджет;
- местоположение;
- сезон;
- доступность продуктов;
- ограничения;
- предпочтения;
- количество приёмов пищи;
- рабочий график;
- уровень активности;
- сложности клиента.

Программа может включать:

- пример меню на день;
- варианты завтрака;
- варианты обеда;
- варианты ужина;
- варианты перекусов;
- список простых замен;
- рекомендации по воде;
- рекомендации по вечерним перекусам;
- рекомендации по сладкому;
- мягкие правила питания без жёстких запретов.

Важно: приложение не должно обещать медицинский результат и не должно заменять индивидуальную консультацию специалиста.

## 23. Обновление материалов

Источник обновлений:

```text
GitHub Raw JSON
```

Логика:

1. Приложение проверяет интернет.
2. Загружает удалённый `content-version.json`.
3. Сравнивает локальную и удалённую версии.
4. Если версия новее — скачивает JSON-файлы.
5. Сохраняет новые материалы локально.
6. Показывает список изменений.
7. Новые материалы применяются только при пересборке программы.

## 29. Критерий готовности MVP

MVP считается готовым, если:

1. Приложение собирается в Windows `.exe`.
2. Клиент может запустить программу на Windows.
3. Клиент видит приветствие нутрициолога.
4. Клиент проходит анкету.
5. Программа собирает персональную программу по шаблонам.
6. Программа учитывает срок 7 / 14 / 21 / 30 дней.
7. Программа показывает меню и рекомендации по питанию.
8. Программа учитывает доступность продуктов, бюджет, сезон и замены.
9. Клиент видит ежедневные задания, привычки и настрой дня.
10. Клиент может отмечать выполнение.
11. Программа фиксирует выполненные и пропущенные дни.
12. Программа показывает прогресс.
13. После пропуска программа мягко возвращает клиента в процесс.
14. Данные сохраняются локально.
15. Приложение работает без интернета.
16. При наличии интернета материалы обновляются через GitHub Raw JSON.
17. Нутрициолог может передать `.exe` клиенту или дать ссылку на скачивание.

## 30. Медицинское предупреждение

Приложение не заменяет врача, психолога, нутрициолога или медицинскую консультацию.

Если у клиента есть диабет, заболевания ЖКТ, почек, сердца, РПП, беременность, лактация, врачебные ограничения, хронические заболевания или другие медицинские особенности, перед использованием программы необходимо проконсультироваться с врачом или профильным специалистом.

Это предупреждение должно быть видно:
